# OnaRadar

AI early-warning registry for pregnant women and newborns (national AI hackathon problem #9):
Red / Yellow / Green zones from clinical rules + trend rules + an ML model, with explanations in Uzbek,
alerts to OvaBMU specialists with an SLA and escalation, and a de-identified AI summary.
**Decision support, not diagnosis. All demo data is synthetic.**

## Run (Windows, prototype mode: SQLite, no Docker)
Requirements: Python 3.11+, Node 20+, Git.

PowerShell (from the repo root):
```powershell
git clone <repo-url> onaradar; cd onaradar
powershell -ExecutionPolicy Bypass -File .\start_all.ps1   # backend (:8000) + frontend (:5173) windows, then the browser
```
Or separately: `.\run_backend.ps1` and `.\run_frontend.ps1` (each in its own terminal). The `.bat` versions
(`start_all.bat`, `run_backend.bat`, `run_frontend.bat`) do the same from cmd or PowerShell.

The first backend run creates `backend\.venv`, installs `requirements-dev.txt`, creates `backend\.env` from
`.env.example` with freshly generated `JWT_SECRET` / `FERNET_KEY`, trains the model (~1 min) and seeds the DB.
To enable the AI summary, put your key in `backend\.env` as `GEMINI_API_KEY=...` and restart the backend.

Checks: `backend\.venv\Scripts\ruff check backend` · `run_tests.bat` (pytest) ·
`cd frontend; npm run typecheck; npm run lint; npm run build`.

| Script | What it does |
|---|---|
| `reset_demo.bat` | Re-seeds the demo DB in ~15 s (stop the backend first): 50–60 active pregnancies + a few newborns per mahalla, ~70% green / ~25% yellow / ~5% red |
| `train_model.bat` | Regenerates synthetic data and retrains; prints ROC-AUC / PR-AUC |
| `run_tests.bat` | Backend tests (pytest) |

Config: `backend\.env` (template: `backend\.env.example`; the run scripts create it on first run with fresh
`JWT_SECRET` / `FERNET_KEY`). `GEMINI_API_KEY` empty → AI summary uses the template fallback (tagged "Shablon");
with a key it calls Google Gemini (`GEMINI_MODEL`, tagged "AI (Gemini)").
`DEMO_MODE=true` → red-alert SLA is `DEMO_SLA_RED_MINUTES` (default 10), so nothing escalates by itself during
a pitch. To show escalation live, the specialist presses **"Demo: SLA muddatini hozir tugatish"** on the alert
row (DEMO_MODE only, audit-logged): the next escalation run (≤30 s) escalates it. Escalation chain (one place:
`backend/app/services/alerts.py`): RED specialist → **OvaBMU bo'lim mudiri** (`department_head`) → district admin
notified with a count only; YELLOW specialist → polyclinic doctor → district admin (count). Telegram: a send-only
adapter (`services/notify.py`) sends de-identified messages (patient code + 3 bullets) when `TELEGRAM_BOT_TOKEN`
and the user's chat id are set, otherwise logs them ("offline"). Escalation runs as an
APScheduler background job every 30 s (started with the backend). Admins can check the LLM integration at
`GET /api/llm/health` (provider, key present, primary/fallback model, last call ok/failed, every attempt of
the last call with its duration and error — never the key itself).

**AI summary timing.** The summary is generated **in the background** right after a visit is saved and cached
per risk assessment; the patient card shows "AI xulosa tayyorlanmoqda…" and polls every 3 s (max 60 s). On
backend start (key present, `LLM_PREWARM=true`) the DEMO1–DEMO4 summaries are pre-generated ~2 s apart.
Attempt chain, all inside `LLM_TIMEOUT_S` (25 s), each attempt ≤ `LLM_ATTEMPT_TIMEOUT_S` (10 s, Gemini's
minimum deadline): `GEMINI_MODEL` (structured) → on 503/504/429/timeout `GEMINI_FALLBACK_MODEL` (structured)
→ one plain-JSON retry if ≥10 s are left → template "Shablon". Models were chosen by a measured benchmark
(task 06): `gemini-3.1-flash-lite` primary, `gemini-3.5-flash-lite` fallback, lowest thinking level.

## AI summary and privacy
The AI summary ("AI xulosa") is generated by **Google Gemini** (`google-genai` SDK) with structured JSON output,
validated against a Pydantic schema; recommended actions are limited to a fixed catalog and a fixed Uzbek
disclaimer is always added. **Only de-identified clinical values** are sent: the pseudonymous patient code,
age, gestational weeks, the last visits' measurements, and the risk engine's rule/trend codes. Never the name,
JShShIR, phone, address, mahalla or free-text notes (allow-list in `backend/app/llm/summary.py`, covered by tests).

**Free vs paid tier.** Under Google's Gemini API Additional Terms of Service (effective 23 March 2026; re-check
before go-live), content sent to *Unpaid Services* may be used by Google to provide, improve and develop its
products, may be read by human reviewers, and Google asks users not to submit sensitive or personal
information. For *Paid Services*, Google states it does not use prompts or responses to improve its products
(they are logged for a limited time for abuse detection). The demo uses synthetic data only; **any use with
real patient data must use a paid (billing-enabled) Gemini API project**, in addition to the de-identification
above and a legal review under ZRU-547.

## Organisation
Region → District → **Polyclinic (oilaviy poliklinika, the tenant)** → Mahalla(s) → Patients.
Staff see only their own polyclinic (one central dependency, `backend/app/api/tenancy.py`), including patient
home points on the mahalla map. District/region admins see **aggregated counts only** (no names, codes or homes).

## Demo story (3 min)
1. Login map: the polyclinic's mahalla on satellite imagery. Log in **PL-NUK-001 / nurse** → mahalla map with
   patient homes coloured by zone.
2. Bemorlar → `QQR-NUK-DEMO1` (19 y, 31 weeks, **YELLOW** by the predictive trend P01 only: diastolic 72 → 78 → 84
   over 3 checkups, projected 90 in 2 weeks; sparkline ↗ in "Nega bu zona?") → **+ Yangi tashrif** →
   BP 152/98, protein **+2**, *Kuchli bosh og'rig'i* → live preview turns **RED** (R02) → save.
3. Log in **PL-NUK-001 / specialist** → Ogohlantirishlar → red alert with the 3-bullet summary and the live
   "Javob berish uchun qoldi" countdown → *Demo: SLA muddatini hozir tugatish* → within 30 s "Bo'lim mudiriga yuborildi".
4. Log in **PL-NUK-001 / department_head** → "Kechikkan ogohlantirishlar" → *Qabul qildim* (or reassign).
5. Log in **region.admin** → O'zbekiston › Qoraqalpog'iston › Nukus shahri › PL-NUK-001: counts only.
